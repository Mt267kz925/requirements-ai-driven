# AI駆動開発を前提とした要件定義の改善検討

ダッシュボードWebアプリ開発を想定して、要件定義フェーズの「現状」と「AI駆動開発でのあるべき姿」を比較し、改善点を整理した一次調査資料です。

> **注意**：資料中の「現状」は、一般的な開発現場を想定した**仮説**です。実際の業務フローをヒアリングしたうえで更新する前提です。

## 要点

- 要件定義の作業は、現状の16件からAI駆動開発では26件（一致9・置換7・追加10）になる
- 人が実行する作業は16件から11件に減り、AIが実行する作業は15件になる
- 人の「作成・整理」の作業はAIに移り、人は「判断・合意」と「AIの出力の確認」に集中する
- 効果が大きいのは、KPI辞書とデータ検証（手戻りの最大要因への対策）と、動くプロトタイプでの合意
